# 125A Arporator V0.1 Behaviour Contract

Status: development contract for `v0.1.0-development`.

## Product goal

Arporator is a musical MIDI arpeggiator that remains immediately understandable while going substantially beyond a basic DAW arp.

The product must not become a BlueARP/Stepic-style programming environment. Complexity belongs in the engine; the primary UI remains direct.

## Timing and trigger invariants

- Pattern length is freely selectable from 1 to 32 steps.
- A fresh phrase in RESTART mode begins at Step 1 at the exact input Note-On sample.
- If the phrase is first triggered at bar 2, Step 1 begins at that trigger in bar 2. There is no hidden globally-running step counter.
- CONTINUE mode changes held note material without resetting the step position.
- Simultaneous Note-On events at one sample form one chord trigger and restart only once.
- MIDI events and generated arp events are evaluated chronologically inside every host block.
- A delayed Swing step must not disappear merely because another MIDI event occurs before the delayed step.
- Note-Off and All-Notes-Off must never leave generated notes stuck.
- All-Notes-Off followed by a new Note-On at the same sample must allow the new phrase to start immediately.
- Transport stop may flush the active arp state for safety; a subsequent fresh trigger starts normally.

## Rate

Initial host-synchronised values:

- 1/4
- 1/8
- 1/16
- 1/32
- 1/64
- 1/8T
- 1/16T
- 1/32T
- 1/8D
- 1/16D
- 1/32D

Default: 1/16.

## Note-order modes

- UP
- DOWN
- UP-DOWN
- DOWN-UP
- PLAYED
- RANDOM

Random behaviour must be deterministic for a fixed seed after reset.

## Pitch policy

- CHORD ONLY: generated pitch stays on pitch classes supplied by the held chord, including octave displacement.
- SCALE: generated pitch is constrained to the selected key/scale.
- CHROMATIC: no pitch-class constraint.

Initial scales:
- Major
- Natural Minor

## Global controls

- Mode
- Rate
- Octaves: 1-4
- Pattern Length: 1-32
- Gate
- Swing
- Trigger: Restart / Continue
- Pitch Policy
- Key
- Scale

Global Gate is the main gate control. Default per-step Gate is neutral (100%), so the global default is not multiplied down unintentionally.

## Per-step data

Each of 32 stored steps has:

- Enable
- Velocity
- Gate multiplier
- Ratchet 1x-4x
- Probability
- Octave offset

Only steps inside the active Pattern Length participate in playback.

## Realtime contract

The final VST3 process path must:

- perform no file or network I/O;
- use no locks;
- perform no logging/string formatting;
- perform no unbounded work;
- perform no heap allocation in normal processing;
- bound event-generation work;
- fail safely under event-capacity pressure;
- preserve Note-Off safety traffic.

Input VST3 events are consumed in sample-offset order. Steinberg's validator explicitly checks input event ordering.

## State / recall

- Stable parameter IDs are mandatory from the first public test build onward.
- Processor state is transferred between host/state thread and audio thread through lock-free snapshots.
- Recall restores all user-relevant global and per-step settings.
- Opening an editor later must not change MIDI behaviour.

## V0.1 musical layer after deterministic core

To be added only after the base engine remains green:

- Humanize
- Strum
- Groove
- Variate + Locks
- Evolve

These features must be controllable, scale-safe where pitch is affected, and neutral at 0%.

## Explicit non-goals for V0.1

- chord sequencer / chord-step engine
- multiple parallel arp tracks
- large modulation matrix
- complex routing pages
- hidden random behaviour when random/probability/evolution controls are neutral
